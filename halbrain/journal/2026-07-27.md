### [20:42] Small-text legibility: real fonts loaded, WCAG AA contrast, 9/10px → 11px (branch: main · commit 975bf05 · PRs #34, #35)
**Synopsis:** User reported small text on the web app is hard to read and asked for whatever gives proper visibility to every visitor. Measured rather than guessed; found three compounding causes, fixed all three, released.
**What worked + Evidence:** Diagnosed by instrumenting the **live production DOM** in the CDT browser — walked every leaf text node ≤13px, resolved its effective background up the tree, and computed WCAG contrast. That produced hard numbers instead of opinion:
- **Contrast was the dominant cause, not the typeface.** Against `--hal-bg-1` (#0a0a0c): `--hal-text-3` #50505a = **2.5:1**, `--hal-text-4` #2e2e36 = **1.5:1**, mobile `--text-muted` #4a4a5a = **2.3:1** — versus the 4.5:1 AA minimum. text-3 alone carries most small labelling (timestamps, @handles, counts, "20 ENTRIES"). New ramp: text-2 #9a9aa6 (7.1), text-3 #8a8a96 (5.8), text-4 #7e7e8c (4.9), mobile muted #7e7e8c (4.9), secondary left at #8a8a9a (5.8) to preserve hierarchy. **Re-measured in-page after applying: every text colour 5.09–18.17:1.**
- **Trap: `#4a4a5a` was hardcoded in 21 files**, not read from `--text-muted` — changing the token alone would have silently missed every mobile timestamp. Swept with sed across `apps/web/src` + `packages/ui/src`.
- **The design system's fonts were never loaded.** `document.fonts` contained only Inter and Instrument Serif; `--hal-sans`/`--hal-mono` name Geist / Geist Mono, which nothing loaded ⇒ fell back to system UI and Consolas/Courier. **`document.fonts.check('12px "Geist"')` returned `true`, which is misleading** — it reports availability including locally-installed faces, and the dev machine has Geist. So the defect was invisible from the inside while every other visitor read 9–11px mono in a fallback face. Loaded both via `next/font/google`, bound to the tokens.
- **Size:** 103 instances of `fontSize: 9`/`10` raised to 11 (sed with `\b` word boundaries — verified afterwards that nothing became `111`/`1111`).
- Left `letter-spacing` (0.14em) alone deliberately: it is real visual language, and at 11px with proper contrast it stops fighting the reader.
**What did NOT work:** My contrast script's `bgOf()` treats a semi-transparent background as opaque, so cyan-on-`rgba(0,212,255,0.15)` reported a bogus **1:1**. Composited properly it is ~8.7:1 — a measurement artefact, not invisible text. Checked before reporting it rather than filing a phantom bug; any future reuse of that script needs alpha compositing. Also re-learned the `packages/ui` **dist** gotcha (5th time this session): it resolves from `dist`, so `theme.ts`/`SearchBar.tsx` colour changes needed `npx tsc` in that package before the app saw them.
